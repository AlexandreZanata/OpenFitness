# Mobile capability matrix — desktop parity at ≤200 MB

> **Phase:** [N-08](../phases/08-mobile-pack/README.md) · **Budget:** 200 MB total pack · **No on-device LLM**

This document maps **desktop NutriOffline behaviour** to the **mobile implementation method**. Parity is defined on **user-visible outcomes** (correct macros, sources, query types), not on using the same 3B GGUF model.

## Business rules (mobile)

Same as RAG V2 — enforced in code, not by a model:

### BR-RET-001 — Source priority

```
GIVEN generic Brazilian food ("arroz 100g")
WHEN hybrid retrieval returns TACO and OFF
THEN selected record MUST prefer TACO if score within 0.05 of top OFF
```

### BR-RET-002 — Numeric grounding

```
GIVEN any mobile response with macros
THEN every number MUST come from retrieved fields via scale_nutrient()
AND MUST NOT be generated by templates except formatting
```

### BR-RET-003 — Multi-item independence

```
GIVEN "arroz 100g, carne 200g"
THEN each item retrieved independently; totals computed in Python
```

### BR-MOB-001 — Pack scope honesty

```
GIVEN query for food not in mobile pack (Tier D)
WHEN confidence below threshold
THEN respond "not found" — never fabricate kcal
```

### BR-MOB-002 — Size budget

```
GIVEN nutri-mobile.pack build
WHEN total size > 200 MB
THEN build MUST fail (CI gate)
```

## Why this works without a 200 MB “LLM”

A 3B parameter model at q4 needs ~1.8 GB — **9× over budget**. The desktop stack already proved that **≥80% of nutrition queries** are factual lookups (RAG V2 benchmark). The remaining “reasoning” queries decompose into:

1. **Retrieve** food A and B  
2. **Compare** numeric columns  
3. **Format** answer in PT-BR  

Steps 1–3 do not require generative parameters on device. Fine-tuning (Phase 5) informed **tone and patterns** — mobile copies those patterns via templates trained from the same golden examples.

Optional future: **≤15 MB intent classifier** (DistilBERT multilingual) if regex coverage falls below 90% on NL intent set — still within budget if index compressed.
